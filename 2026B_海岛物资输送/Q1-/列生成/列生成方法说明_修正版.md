# 列生成方法求解海岛物资输送问题 (修正版)

## 一、算法概述

列生成（Column Generation）是一种用于求解大规模线性/整数规划的分解算法。其核心思想是：当问题的决策变量（"列"）数量极其庞大时，不一次性生成所有列，而是在求解过程中根据需要动态生成能改进目标函数的列。

对于本题，每一个"列"代表一条完整的航行方案——包含路径序列、每日工作天数、各补给站的采购量。所有可行方案构成集合 R。主问题从 R 中恰好选择一条路径。

## 二、数学建模

### 2.1 主问题

设 R 为所有可行路径的集合。对每条路径 r in R，定义 Z(r) 为抵达终点时携带的目标物资，M(r) 为剩余资金，a_r in {0,1} 为是否选择路径 r。

主问题为：max sum Z(r)*a_r，s.t. sum a_r = 1，a_r in {0,1}。这只有一条凸性约束（恰好选一条路径），其 LP 松弛的最优解等于 max Z(r)，对偶变量 pi = Z_max。

### 2.2 定价子问题

检验数（reduced cost）：c_r = Z(r) - pi。若 Z(r) > Z_current，则加入该列可改进目标。定价子问题：找到可行路径 r 使 Z(r) > Z_current，或证明不存在。

### 2.3 定价求解

通过骨架枚举 + 贪婪前向模拟：外层枚举路径骨架 B->{W1,W2,W3,S1,S2}的排列->E，过滤总旅行<=30天；中层枚举各作业点工作天数（0到max_consec），过滤总天数<=30；内层贪婪前向模拟——逐日追踪资源，补给日按"刚好够到下一个补给点"采购，检查载重<=120和非负约束。

**修正说明**：原版 gsim 函数在补给到达日遗漏了当日移动资源消耗（if/else 分支跳过了 else 中的消费逻辑），导致每经过一次补给点多计 O=2, H=3, F=2。修正后，资源每日必定先消耗后采购，M 值得到正确计算。

## 三、算法流程

1. Pool = {B->E直接路径}
2. Z* = max Pool中Z
3. 循环：pi = Z*; 搜索骨架空间找Z(r)>pi的新列; 找到则加入Pool; 否则终止
4. 返回最优路径

## 四、收敛性

主问题仅一条约束，每次改进列严格提升Z*。骨架空间有限（实际542种可行骨架，含0~7个中间点），工作天数组合有限，有限次迭代必然收敛。列生成通过"逐步改进"达到与全枚举相同的最优解。

## 五、实验结果

| 指标 | 值 |
|------|:--:|
| 最优 Z | 288 |
| 最优 M | 22 |
| 路径 | B->W1->S2->W3->S2->W3->E |
| 生成列数 | 15 |
| 定价迭代 | 16 |
| 旅行天数 | 23 |
| 工作天数 | 7 (W1:1, W3:3+3) |
| 总天数 | 30 |

对偶变量 pi 从100单调递增到288，中间经过120, 140, 160, 180, 184, 200, 205, 220, 225, 240, 244, 260, 264, 268等值，体现了路径池质量的逐步提升。

## 六、对偶变量的经济学解释

对偶变量 pi 代表"影子价格"——在仅有唯一凸性约束时，pi 即为当前池中最优列的 Z 值。检验数 Z(r)-pi>0 意味着新路径的Z值超过了当前池的"市场价"。最终pi稳定在288，再无新路径能超越。

## 七、方法评价

优点：对偶理论保证全局最优（在骨架+工作天数的有限枚举空间内）；天然支持并行化；可扩展至30x30网格（任务3）；迭代过程直观。

局限：本题枚举空间小（542骨架），列生成overhead大于纯枚举；定价子问题本身是NP-hard的RCSP；主问题仅一条约束导致退化。

## 八、与骨架枚举对比

纯枚举一次性评估所有542个骨架的全部工作天数组合。列生成通过16次迭代逐步改进达到同样结果。在本题中时间几乎相同（0.17s vs 0.18s），但在30x30网格的任务3中列生成优势显著。

## 九、Bug 修正记录

**原版 bug**：`gsim` 函数中，补给到达日（`isSup(t)=true`）资源消耗被 `if/else` 跳过，导致：
- 每次经过补给点未扣除当日移动消耗（O=2, H=3, F=2）
- 资源余额被高估，采购量被低估
- M 值从正确的 22 被错误计算为 44

**修正方案**：将每日资源消耗（`O=O-cO(t); H=H-cH(t); F=F-cF(t)`）提至 `if/else` 之前，确保无论是否补给日均先消耗再采购。修正后 Z=288 不变，M 从 44 修正为 22。
