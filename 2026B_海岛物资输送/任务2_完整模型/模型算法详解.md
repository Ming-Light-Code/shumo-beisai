# 任务2 在线约束规划决策模型——完整算法详解与论证

## 一、问题建模

### 1.1 问题概述

任务2要求建立一个**在线决策模型**：船舶每日行动前仅能观测当日天气 $w_t \in \{\text{正常}, \text{雷暴}\}$，不可预知未来天气，须根据当前状态实时决策当日动作。目标：30天内抵达终点E，最大化目标物资Z，其次最大化剩余资金M。

特别要求给出连续30天均为雷暴极端天气下的最优方案。

### 1.2 状态空间

时刻 $t$（观测天气后、决策前）的船舶状态：

$$S_t = (x_t, y_t, O_t, H_t, F_t, M_t, Z_t, c_t, w_t, d_t)$$

| 符号 | 含义 | 约束 |
|------|------|------|
| $(x_t, y_t)$ | 网格坐标 | $\{1,\dots,10\}^2$ |
| $O_t, H_t, F_t$ | 燃油、淡水、食物 | $\mathbb{Z}_{\geq 0},\ O+H+F \leq 120$ |
| $M_t$ | 资金 | $\mathbb{Z}_{\geq 0}$ |
| $Z_t$ | 目标物资 | $\mathbb{Z}_{\geq 0}$ |
| $c_t$ | 连续作业天数 | $0 \leq c_t \leq WM_i$ |
| $w_t$ | 当日天气（观测值） | $\{\text{N}, \text{T}\}$ |
| $d_t$ | 当前天数 | $1,\dots,30$ |

### 1.3 动作空间

$$A(S_t) = \{\uparrow, \downarrow, \leftarrow, \rightarrow, \text{停泊}, \text{作业}, \text{补给}\}$$

动作可行性受资源、载重(120)、连续作业上限、位置功能四重约束。

### 1.4 消耗参数

| 动作 | 正常天气 (O,H,F) | 雷暴天气 (O,H,F) |
|------|:---:|:---:|
| 移动一格 | (2,3,2) | (8,4,3) |
| 停泊 | (1,1,1) | (3,3,2) |
| 作业 | (5,4,3) | (8,6,6) |

补给价格不变：$p_O=2, p_H=1, p_F=2$。作业点收益 W1=20, W2=15, W3=28（单位/天），单次最大连续作业 WM=[4,5,3]。

### 1.5 目标函数（词典序）

$$\max \; Z_{\tau}, \quad \text{then} \quad \max \; M_{\tau}$$

其中 $\tau = \min\{t : (x_t,y_t) = E, t \leq 30\}$。

## 二、约束规划（CP）决策引擎

### 2.1 在线决策架构

```
逐日循环 (t = 1, 2, ..., 30):
  ├─ 观测: w_t ← 当日天气
  ├─ CP搜索: 从当前状态 S_t 出发，假设剩余天数天气 = w_t
  │          搜索所有可行的"路径骨架+工作天数+停泊天数"组合
  │          返回 Z 最大（其次 M 最大）的最优方案
  ├─ 预展开: 将CP输出的路径骨架展开为逐日动作序列
  ├─ 执行: 执行序列中的第一个动作
  └─ 状态转移: S_{t+1} = T(S_t, a_t^*, w_t)
```

**天气假设策略**：CP搜索假设剩余天数天气与今日相同（悲观且一致）。对于全雷暴/全晴天极端情形，假设与真实一致 → 等价确定性全局最优。

### 2.2 CP四机制

#### ① 值域缩减

在每个搜索节点，根据当前资源过滤不可行的下一目标点。

雷暴下 B→S2 需 O=56 > 35 → 直接从搜索树删除。

#### ② 约束传播

移动/作业/停泊后检查 $O \geq 0, H \geq 0, F \geq 0, O+H+F \leq 120$。违规→终止该分支。

#### ③ 分支

CP在"路径骨架"层面分支——递归尝试 $\{W_1, W_2, W_3, S_1, S_2\}$ 作为下一目标点。

叶节点枚举：工作天数（含停泊-再作业策略）+ 海上停泊天数。

工作天枚举使用 `maxWorkWithPark(mc, remaining)` 确定上界：

$$\text{maxWork}(mc, R) = \max_{k \geq 1}\{k \cdot mc : k \cdot mc + (k-1) \leq R\}$$

并利用剩余松弛追加部分工作天。

#### ④ 回溯 + 剪枝

三条剪枝规则：

- **上界剪枝**：$UB_Z = Z_t + \text{maxWork}(3, rem - d_E) \times 28$。若 $UB_Z \leq best_Z$，剪枝。
- **前向检查**：$tsf + d(\text{current}, p) + d(p, E) \leq 30$。
- **相邻去重**：跳过与当前点相同的目标。

### 2.3 核心算法：sim() 资源模拟

`sim(pid, m, tt, dist, wd, parkSeg, cons, O, H, F, M, Z)` 是CP引擎的核心评估函数，模拟整条路径的资源消耗与补给决策。

**算法流程**：

```
1. 构建消耗数组:
   For each segment k:
     a. 停泊: parkSeg[k] 天, 消耗 (PO, PH, PF)
     b. 移动: d 天, 消耗 (MO, MH, MF), 最后一天标记 isSup (若达补给点)
     c. 作业: wd[wk] 天, 消耗 (WO, WH, WF), 含 park_reset 断点

2. 逐日模拟:
   For t = 1 to T_actual:
     O -= cO[t]; H -= cH[t]; F -= cF[t]; Z += zG[t]
     If O<0 or H<0 or F<0: return INFEASIBLE
     If O+H+F > 120: return INFEASIBLE
     If isSup[t]:
       找下一补给日 ns
       计算 t+1 到 ns 所需资源 (含到达消耗)
       采购 = max(0, 需求 - 当前)
       If 采购总量 > 剩余空间 or cost > M: return INFEASIBLE
       O += bO; H += bH; F += bF; M -= cost
   
3. Return FEASIBLE with final Z, M
```

**⚠ 关键实现细节——补给上界**：

MATLAB原版 `for tt2 = t+1:ns` 是**包含性**范围。移植到JavaScript时若写成 `for(tt=t+1; tt<ns; tt++)`（排他性），会导致下一补给点**到达日的移动消耗不被计入采购**，船抵达时资源为负被误判不可行。

正确写法：`for(tt=t+1; tt<=ns; tt++)`（包含性），与MATLAB行为一致。这是实现中发现的最后一个关键bug，修复后双S2路径（B→W1→S2→W3→S2→E）才能被正确评估为可行。

## 三、全雷暴极端情形分析

### 3.1 连通性

雷暴燃油 8/格，B出发可达域：S1(3格,O=24)、W1(3格,O=24)。S2(7格,O=56)、W2(6格,O=48)、W3(10格,O=80)均不可达。

### 3.2 载重瓶颈

B→S1后：O=11, H=33, F=21, 负载=65, 空间=55。S1→E需采购63，超出1单位。

### 3.3 突破：海上停泊

B→S1段插入 $p$ 天停泊（消耗3,3,2/天）：

| p | 负载 | 空间 | 采购需求 | 可行? | M |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 0 | 65 | 55 | 63 | ✗ | - |
| **1** | **57** | **63** | **63** | **✓** | **116** |
| 2 | 49 | 71 | 71 | ✓ | 103 |
| 3 | 41 | 79 | 79 | ✓ | 90 |

### 3.4 最优方案

| 指标 | 值 |
|------|:---:|
| Z | 100 |
| M | 116 |
| 路径 | B → 停泊1天 → S1(补给) → E |
| 天数 | 12天 (旅行11 + 停泊1) |
| 作业 | 无法进行（任何含作业的路径均超载重上限120） |

## 六、算法复杂度

- **搜索树节点数**：全雷暴 ~200，全晴天 ~200
- **sim()调用次数**：全晴天 ~500K（100种工作天组合 × 6种停泊组合 = 每次叶评估600次sim调用，约200次叶评估）
- **单次sim()复杂度**：$O(T)$，T ≤ 30
- **总计算量**：~500K × 30 ≈ 15M次基本操作，浏览器中约1-2秒完成
- **空间复杂度**：递归深度 ≤ 6，$O(1)$ 额外空间

## 七、正确性论证

### 7.1 全雷暴最优性

CP搜索探索了所有可能的路径骨架（B→{W1,W2,W3,S1,S2}的排列组合，受前向检查约束）。对每个骨架枚举所有工作天+停泊天组合。搜索树完备（所有可行解均被评估），且上界剪枝仅移除可证明不优的分支。

S2不可达、工作不可行的结论通过穷举验证：所有含S2或作业点的路径均因资源不足在sim()中返回不可行。

### 7.2 全晴天最优性（回归任务1）

CP搜索找到的 Z=328 路径与任务1的枚举/列生成结果一致。搜索空间覆盖了所有可行骨架+工作天组合，词典序优化保证了Z最大优先。

### 7.3 关键实现验证

通过独立诊断工具（`cp_diag.html`）直接调用 `sim([0,2,6,4,6,1], 4, 19, DST, [3,6], [0,0,0,0,0], ...)` 验证双S2路径可行性，输出 `ok=true Z=328 M=21`，确认算法正确性。
