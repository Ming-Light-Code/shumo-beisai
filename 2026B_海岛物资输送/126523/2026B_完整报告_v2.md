# 2026B 海岛物资输送问题 —— 完整竞赛报告

---

## 摘要

本文针对东南大学第十九届数学建模竞赛 B 题"海岛物资输送问题"，构建统一**约束规划（Constraint Programming, CP）**框架，分别求解三类天气条件下的最优航行方案。

- **任务1（正常天气）**：建立离线全局 CP 模型，通过路径骨架搜索 + 工作天数枚举 + 停泊重置策略，求得最优解 **Z=328, M=21**。
- **任务2（天气仅当日可观测）**：首先建立了通用**在线约束规划决策模型**——船舶每日观测天气后，基于当前状态、当日天气和剩余资源进行 CP 前向搜索，产出最优动作。该模型在**全雷暴**极端天气下退化为 B→停泊1天→S1→E（Z=100, M=116），在**全正常**天气下退化为任务1的最优解（Z=328, M=21），完美验证了模型的一致性和退化能力。
- **任务3（随机天气）**：引入**期望值消耗参数**，将随机天气平滑为确定性 CP 模型，求得最优解 **Z=480, M=9**；资金约束成为30×30网格、90天时限下的主导瓶颈。

**关键词**：约束规划；在线决策；期望值模型；海上停泊策略；退化验证

## 一、问题重述

### 1.1 场景描述

某航海物流承运方负责一片专属网格化海域内的物资输送任务。船舶从起始岛 B 出发，需要抵达终点交付岛 E，并在抵达时交付所携带的目标物资 Z。航行途中可以依托海上补给平台 S1、S2 补充自持资源（燃油 O、淡水 H、食物 F），也可以在指定海上作业点位 W1、W2、W3 开展作业增加目标物资存量。船舶每日可选择向上、下、左、右四个方向移动一格，或在原地停泊。

### 1.2 三任务核心差异

| 参数 | 任务1 | 任务2 | 任务3 |
|------|:---:|:---:|:---:|
| 网格规模 | 10×10 | 10×10 | 30×30 |
| 时限 | 30天 | 30天 | 90天 |
| 初始 (O,H,F) | (35,45,30) | (35,45,30) | (100,150,100) |
| 初始 M / Z | 240 / 100 | 240 / 100 | 750 / 200 |
| 载重上限 | 120 | 120 | 400 |
| 天气 | 不考虑 | **仅知当日天气**，可为任意序列 | 独立随机：P(正常)=0.8 |

### 1.3 消耗参数与点位坐标

| 动作 | 正常天气 (O,H,F) | 雷暴天气 (O,H,F) |
|------|:---:|:---:|
| 移动（每格） | (2, 3, 2) | (8, 4, 3) |
| 停泊（每天） | (1, 1, 1) | (3, 3, 2) |
| 作业（每天） | (5, 4, 3) | (8, 6, 6) |

补给价格不变：p_O=2, p_H=1, p_F=2。

| 点位 | 坐标 (任务1,2) | 坐标 (任务3) | 收益/天 | Max连续作业 |
|------|:---:|:---:|:---:|:---:|
| B(起点) | (1,5) | (1,15) | — | — |
| E(终点) | (10,5) | (30,15) | — | — |
| S1(补给) | (3,4) | (12,16) | — | — |
| S2(补给) | (7,6) | (21,16) | — | — |
| W1 | (2,7) | (6,21) | 20 | 4 |
| W2 | (5,3) | (15,9) | 15 | 5 |
| W3 | (8,8) | (24,24) | 28 | 3 |

### 1.4 共用方法框架

三个任务统一使用**约束规划**框架求解，核心机制为：值域缩减 → 约束传播 → 递归分支 → 回溯剪枝。仅在**消耗参数层**做适配。

## 二、任务1：正常天气下离线全局最优规划

### 2.1 问题分析

任务1不考虑天气，所有消耗参数确定。正常天气下消耗较低（移动仅 2,3,2/格），载重和资金相对充裕，真正限制收益的是**连续作业上限**。W3 收益最高（28/天），但单次最多连续作业仅3天。若想作业超过3天，要么离开后返回（消耗大量旅行天数），要么在 W3 原地停泊1天重置计数器。

### 2.2 数学模型

#### 决策变量

- 路径骨架：P = (B, p_1, ..., p_k, E), p_i ∈ {W1, W2, W3, S1, S2}
- 工作天数：w_j ∈ Z+，j = 1,...,k
- 停泊日数：若作业需拆分，通过 ceil(w_j/WM_i) − 1 个停泊日分隔

#### 约束

(1) 载重约束：∀t, O_t + H_t + F_t ≤ 120
(2) 非负约束：∀t, O_t ≥ 0, H_t ≥ 0, F_t ≥ 0
(3) 连续作业上限：单次 ≤ WM_i（W1=4, W2=5, W3=3）
(4) 时间窗：总旅行天数 + 总停留天数 ≤ 30
(5) 资金约束：补给花费 ≤ 当前 M

#### 目标函数（词典序）

max Z，其次 max M（Z 和 M 为抵达 E 时的值）。

### 2.3 约束规划求解策略

**路径骨架递归搜索**：从 B 出发，递归尝试中间点 {W1, W2, W3, S1, S2}，路径以 E 结尾为叶节点。到达叶节点后，枚举所有可行的工作天数组合，调用模拟函数 simulate() 评估。

**三条剪枝规则**：

规则1——**上界剪枝**：在任意节点 (pos, t)，最乐观假设剩余天数全部在 W3（收益 28/天）作业：
`
UB_Z = 100 + max_work_with_park(WM=3, R = 30−t−dist(pos,E)) × 28
`
若 UB_Z ≤ best_Z，剪掉整棵子树。

其中 max_work_with_park(mc, R) 计算在 R 天内（含停泊日）最多可作业天数：
`
max_{k≥1} { k·mc | k·mc + (k−1) ≤ R }
`
并利用剩余松弛 min(mc, slack−1) 追加部分工作日。

规则2——**前向检查**：添加点 p 前验证 t_sf + dist(curr,p) + dist(p,E) ≤ 30。
规则3——**相邻去重**：跳过与当前位置相同的点。

### 2.4 最优解

| 指标 | 值 |
|------|:---:|
| **Z** | **328** |
| **M** | **21** |
| 路径 | B → W1 → S2 → W3 → S2 → E |
| 旅行距离 | 19 格 |
| 工作安排 | W1=3天, W3=3+停1+3=6天 |
| 总天数 | 29 天 |
| CP 搜索节点 | 192 |

#### 逐日明细

| 日期 | 动作 | O+H+F | Z | M | 说明 |
|:---:|------|:---:|:---:|:---:|------|
| 1–3 | B→W1 移动 3格 | 110→89 | 100 | 240 | |
| 4–6 | W1 作业×3 | 89→53 | 160 | 240 | 收益 20/天 |
| 7–12 | W1→S2 移动 6格 | 53→17 | 160 | 240 | |
| 12 | S2 **补给** | 120 | 160 | **65** | 购O=41,H=37,F=28 (花费175) |
| 13–15 | S2→W3 移动 3格 | 99→78 | 160 | 65 | |
| 16–18 | W3 作业×3 | 78→42 | 244 | 65 | 会话1: Z+84 |
| 19 | W3 停泊 | 39 | 244 | 65 | 重置计数器 |
| 20–22 | W3 作业×3 | 3 | **328** | 65 | 会话2: Z+84 |
| 23–25 | W3→S2 移动 3格 | — | 328 | 65 | |
| 25 | S2 **补给** | — | 328 | **21** | 购O=8,H=12,F=8 (花费44) |
| 26–29 | S2→E 移动 4格 | — | 328 | 21 | |

**验算**：Z = 100 + 3×20 + 6×28 = 328，M = 240 − 175 − 44 = 21。

### 2.5 最优性论证

CP 搜索探索了所有可能的路径骨架（排列组合，受前向检查约束）。对每个骨架枚举了所有可行的工作天数+停泊天数组合。上界剪枝仅移除**可证明不优**的分支（UB_Z ≤ best_Z）。搜索树完备，192个节点完成收敛。通过独立调用模拟函数验证关键方案，确认 Z=328, M=21。

## 三、任务2：在线约束规划决策模型与极端天气求解

### 3.1 问题分析

任务2引入了天气影响——船舶**每日行动开始前仅能观测当日天气**，无法预知未来。这是问题的关键特征：决策必须**在线**执行，且决策模型对**任意天气序列**都通用。

题目随后要求"以连续30天均为雷暴天气的极端天气下，给出最优航行方案"。这意味着模型需在全雷暴输入下，自动产出该极端情况的最优解。

更关键的是——合理的在线决策模型在**全正常天气**输入下，也应退化到任务1的最优解（Z=328, M=21）。这是衡量模型一致性、确保方法论统一的根本检验。

**核心思路**：在每个决策日，以"假设未来天气与今日相同"为前向假设，运行 CP 全局搜索，得出从当前状态到终点的最优计划，然后仅执行该计划的第一个动作。次日重新观测天气，若不变则继续；若突变则重新规划。

### 3.2 通用在线决策数学模型

#### 3.2.1 状态空间

时刻 t（观测天气后、决策动作前）的船舶状态为八元组：

`
S_t = ( pt, O_t, H_t, F_t, M_t, Z_t, c_t, w_t, d_t )
`

| 符号 | 含义 | 值域 |
|------|------|------|
| pt | 当前点位索引 | {1(B),2(E),3(W1),4(W2),5(W3),6(S1),7(S2)} |
| O_t,H_t,F_t | 资源余量 | Z≥0, O+H+F ≤ 120 |
| M_t | 剩余资金 | Z≥0 |
| Z_t | 目标物资存量 | Z≥0 |
| c_t | 连续作业天数 | [0, WM_i] |
| w_t | 当日天气观测值 | {N(正常), T(雷暴)} |
| d_t | 当前天数 | {1,...,30} |

#### 3.2.2 动作空间

`
A(S_t) = { ↑, ↓, ←, →, 停泊, 作业, 补给 }
`

动作可行性由四重约束过滤：

- **移动**：需 O_t ≥ c_O(w_t), H_t ≥ c_H(w_t), F_t ≥ c_F(w_t)，且 d_t < 30
- **停泊**：任何网格均可执行（无条件）
- **作业**：仅当 pt ∈ {W1,W2,W3} 且 c_t < WM_i
- **补给**：仅当 pt ∈ {S1,S2}，触发采购算法

#### 3.2.3 前向 CP 搜索与决策函数

在每个决策日 t，系统以当前状态 S_t 为起点，假设剩余天数天气与**今日观测 w_t 完全相同**，运行 CP 全局搜索：

`
Π_t* = CP_Search(S_t, assume(w_{t+1:30} = w_t))
`

其中 Π_t* = (P_t*, W_t*, Park_t*) 包含最优路径骨架、工作天数向量和海上停泊日分配。

决策函数为：**a_t* = first_action(Π_t*)**，即仅执行计划中的第一个动作。

#### 3.2.4 在线决策循环

`
for t = 1:30:
    w_t ← 观测当日天气
    if 第一天 or 天气已变 or 无当前计划:
        Π_t* ← CP_Search(S_t, assume(w_{t+1:30} = w_t))
    执行 Π_t* 的下一动作 a_t*
    更新 S_{t+1}
    if pt == E: 任务完成
`

**设计理由**：在 "假设未来 ≡ 今日" 的前提下，CP 搜索 → 确定性全局最优。全雷暴和全正常两种极限情形下，该假设与真实完全一致，因此搜索结果必然与离线全局最优解吻合。

#### 3.2.5 状态转移规则

按动作类型查消耗表扣除资源：作业累加 Z 和 c_t；停泊清零 c_t；移动更新网格位置；到达补给点触发采购算法（计算至下一补给日或终点的需求，在载重约束下采购差额）。

### 3.3 全雷暴极端天气下的求解

#### 3.3.1 连通性分析

雷暴下移动消耗升至 (8,4,3)/格：

`
B → S1: 3格, O_need = 24 ≤ 35  ✓ (可达)
B → S2: 7格, O_need = 56 > 35  ✗ (不可达)
B → W1: 3格, O_need = 24 ≤ 35  ✓
B → W2: 6格, O_need = 48 > 35  ✗
B → W3: 10格, O_need = 80 > 35 ✗
`

仅 S1 和 W1 可达。S2、W2、W3 均不可达。雷暴大幅收缩了可达域。

#### 3.3.2 载重瓶颈

考虑 B → S1 → E 路径：
- B→S1(3格)：消耗 O=24，到达时 O=11,H=33,F=21，负载=65，载重余量=55
- S1→E(8格)需购：O=53, H=0, F=3，合计 **56 > 55**——超出载重上限1单位！

#### 3.3.3 海上停泊突破瓶颈

雷暴下停泊消耗 (3,3,2)/天高于正常天气，这反而成为优势——主动停泊消耗资源、降低当前负载，为 S1 补给采购腾出空间：

| 停泊 p 天 | 到达S1负载 | 载重余量 | 采购需求 | 可行？ | M 剩余 |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 0 | 65 | 55 | 56 | ✗ | — |
| **1** | 57 | **63** | 63 | **✓** | **116** |
| 2 | 49 | 71 | 71 | ✓ | 103 |
| 3 | 41 | 79 | 79 | ✓ | 90 |

最优：**p=1天，M=116**。

#### 3.3.4 作业不可行证明

S1 最大可购 O = 余量8 + 载重空间63 = 71。含作业的路径：
`
S1→W1→E: O_travel = 32+80 = 112 > 71  ✗
S1→W2→E: O_travel = 24+56 = 80  > 71  ✗
S1→W3→E: O_travel = 72+40 = 112 > 71  ✗
`
所有含作业路径的燃油需求均超过 S1 最大采购能力。**雷暴天气下作业完全不可行**。Z 恒为 100，优化目标退化为 max M。

#### 3.3.5 全雷暴最优解

| 指标 | 值 |
|------|:---:|
| **Z** | **100** |
| **M** | **116** |
| 路径 | B → 停泊1天 → S1 → E |
| 总天数 | 12 天 |
| 策略要点 | 停泊1天消解载重瓶颈（从 56→63），直赴终点 |

#### 3.3.6 独立枚举交叉验证

遍历停泊天数 p=0,1,2,3，枚举计算每种方案在 S1 的补给可行性与最终 M。枚举结果 p=1, M=116，与 CP 搜索结果完全一致。CP 探索约 200 个节点收敛。

### 3.4 模型退化验证 ★核心论证★

**退化验证**是检验在线决策模型一致性的核心步骤：同一个模型，在极端天气输入下能否产出已验证的最优解？

#### 退化场景 1：全雷暴（30 天均为 T）

在线模型逐日观测到雷暴 → 前向假设"未来全雷暴" → CP 搜索产出计划 B→停泊1天→S1→E → 逐日执行：

| 日期 | 动作 | Z | M |
|:---:|------|:---:|:---:|
| 1 | park(at sea) — 停泊1天 | 100 | 240 |
| 2–4 | move B→S1 (3格，雷暴消耗) | 100 | 240 |
| 4 | **SUPPLY(S1)** +O53,H7,F3 cost=124 | 100 | **116** |
| 5–12 | move S1→E (8格) | 100 | 116 |

**退化结果：Z=100, M=116**，与 3.3.5 节独立求解完全一致。✅

#### 退化场景 2：全正常（30 天均为 N）

在线模型逐日观测到正常天气 → 前向假设"未来全正常" → CP 搜索产出计划 B→W1→S2→W3→S2→E → 逐日执行：

| 日期 | 动作 | Z | M |
|:---:|------|:---:|:---:|
| 1–3 | move B→W1 | 100 | 240 |
| 4–6 | work(W1) ×3 | 160 | 240 |
| 7–12 | move W1→S2 | 160 | 240 |
| 12 | SUPPLY(S2) +O41,H37,F28 cost=175 | 160 | **65** |
| 13–15 | move S2→W3 | 160 | 65 |
| 16–18 | work(W3) ×3 | 244 | 65 |
| 19 | park(reset) | 244 | 65 |
| 20–22 | work(W3) ×3 | **328** | 65 |
| 23–25 | move W3→S2 | 328 | 65 |
| 25 | SUPPLY(S2) +O8,H12,F8 cost=44 | 328 | **21** |
| 26–29 | move S2→E | 328 | 21 |

**退化结果：Z=328, M=21**，与任务1最优解完全一致。✅

#### 退化验证结论

| 天气输入 | 期望最优解 | 在线模型输出 | 判定 |
|------|:---:|:---:|:---:|
| 全雷暴 (T×30) | Z=100, M=116 | Z=100, M=116 | ✅ 一致 |
| 全正常 (N×30) | Z=328, M=21 | Z=328, M=21 | ✅ 一致 |

在线决策模型在两种极限天气下均准确退化到各自的离线最优解。这验证了：
1. **前向假设 "未来 ≡ 今日" 在确定性天气下的正确性**——因为它就是真实情况
2. **CP 搜索的完备性**——在全正常下找到了任务1离线求解器得出的同一最优路径
3. **模型的一致性**——同一个模型、同一套代码，仅切换天气序列变量，即产出不同场景下的最优解

### 3.5 MATLAB 代码实现：	ask2_online_decision.m

在线决策模型由两个文件构成：主控制器 	ask2_online_decision.m 和公共函数库 cp_common.m（见附录A）。以下为核心代码（完整实现见源文件，此处保留完整模型结构）：

`matlab
function task2_online_decision()
%% ===== 参数初始化 =====
MAX_DAYS = 30; MAX_LOAD = 120;
all_xy = [1 5; 10 5; 2 7; 5 3; 8 8; 3 4; 7 6];
names  = {'B','E','W1','W2','W3','S1','S2'};
WY = [20, 15, 28];  WM = [4, 5, 3];
INIT_O=35; INIT_H=45; INIT_F=30; INIT_M=240; INIT_Z=100;

% 距离矩阵（曼哈顿距离）
dist = zeros(7);
for i=1:7, for j=1:7
    dist(i,j)=abs(all_xy(i,1)-all_xy(j,1))+abs(all_xy(i,2)-all_xy(j,2));
end; end
inter_idx = [3 4 5 6 7];  % 可选的中间点索引

% 消耗参数表
cons_N = struct('MO',2,'MH',3,'MF',2,'PO',1,'PH',1,'PF',1,...
               'WO',5,'WH',4,'WF',3,'pO',2,'pH',1,'pF',2);
cons_T = struct('MO',8,'MH',4,'MF',3,'PO',3,'PH',3,'PF',2,...
               'WO',8,'WH',6,'WF',6,'pO',2,'pH',1,'pF',2);

%% ===== 天气序列配置 =====
% 验证全雷暴退化：设为 'all_thunder'
% 验证全正常退化：设为 'all_normal'
weather_mode = 'all_thunder';
switch weather_mode
    case 'all_thunder', weather_seq = repmat('T', 1, MAX_DAYS);
    case 'all_normal',  weather_seq = repmat('N', 1, MAX_DAYS);
    case 'mixed',       weather_seq = [repmat('T',1,1), reps('N',1,MAX_DAYS-1)];
end

%% ===== 初始化状态 =====
state.pt=1; state.pos=all_xy(1,:);
state.O=INIT_O; state.H=INIT_H; state.F=INIT_F;
state.M=INIT_M; state.Z=INIT_Z; state.consec=0; state.day=0;
plan_path=[]; plan_parks=[]; plan_works=[]; plan_leg=1;
step_in_leg=0; parked_in_leg=0; wp_idx=0; wd_done=0;

%% ===== 逐日在线决策主循环 =====
while state.day < MAX_DAYS && state.pt ~= 2
    state.day = state.day + 1;
    w = weather_seq(state.day);
    if w == 'T', cons = cons_T; wname = 'thunder';
    else,        cons = cons_N; wname = 'normal';
    end

    % --- CP 重规划触发条件 ---
    if isempty(plan_path) || ...
       (state.day > 1 && w ~= weather_seq(max(1,state.day-1)))
        elapsed = state.day - 1;
        init_s = struct('O',state.O,'H',state.H,'F',state.F,...
                        'M',state.M,'Z',state.Z);
        [plan_path, plan_parks, plan_works, feasible] = ...
            cp_plan(state.pt, elapsed, cons, dist, inter_idx, ...
                    WY, WM, MAX_DAYS, MAX_LOAD, init_s);
        if ~feasible, fprintf('Day %d: 无可达方案！\n', state.day); break; end
        plan_leg = 1; step_in_leg = 0; parked_in_leg = 0;
        wp_idx = 0; wd_done = 0;
    end

    next_pt = plan_path(plan_leg + 1);

    % --- 动作决策（优先级：作业 > 停泊重置 > 海上停泊 > 移动）---
    is_work_pt = (state.pt >= 3 && state.pt <= 5);
    need_work  = is_work_pt && wp_idx < length(plan_works) && ...
                 wd_done < plan_works(wp_idx+1);

    if need_work
        wk_type = state.pt - 2;
        if state.consec < WM(wk_type)
            % 执行作业
            state.O = state.O - cons.WO; state.H = state.H - cons.WH;
            state.F = state.F - cons.WF; state.Z = state.Z + WY(wk_type);
            state.consec = state.consec + 1; wd_done = wd_done + 1;
            if wd_done >= plan_works(wp_idx+1)
                wp_idx = wp_idx + 1; wd_done = 0;
            end
        else
            % 达到连续作业上限 → 停泊重置计数器
            state.O = state.O - cons.PO; state.H = state.H - cons.PH;
            state.F = state.F - cons.PF; state.consec = 0;
        end
    elseif plan_leg <= length(plan_parks) && ...
           parked_in_leg < plan_parks(plan_leg)
        % 海上停泊（任务2关键：降低载重，为补给腾空间）
        state.O = state.O - cons.PO; state.H = state.H - cons.PH;
        state.F = state.F - cons.PF; state.consec = 0;
        parked_in_leg = parked_in_leg + 1;
    elseif step_in_leg < dist(state.pt, next_pt)
        % 移动（曼哈顿走法：先 x 方向后 y 方向）
        state.O = state.O - cons.MO; state.H = state.H - cons.MH;
        state.F = state.F - cons.MF; state.consec = 0;
        step_in_leg = step_in_leg + 1;
        fr = all_xy(state.pt, :); to = all_xy(next_pt, :);
        dx_tot = to(1)-fr(1); dy_tot = to(2)-fr(2);
        sx = abs(dx_tot); sy = abs(dy_tot);
        if step_in_leg <= sx
            state.pos(1)=fr(1)+sign(dx_tot)*step_in_leg; state.pos(2)=fr(2);
        else
            state.pos(1)=to(1); state.pos(2)=fr(2)+sign(dy_tot)*(step_in_leg-sx);
        end
        if step_in_leg >= dist(state.pt, next_pt)
            state.pt = next_pt; state.pos = all_xy(next_pt, :);
            step_in_leg = 0; parked_in_leg = 0;
            % 到达补给点 → 触发采购算法
            if state.pt == 6 || state.pt == 7
                rem_t = 0; rem_p = 0;
                for k = plan_leg:length(plan_path)-2
                    rem_t = rem_t + dist(plan_path(k+1),plan_path(k+2));
                    if k+1 <= length(plan_parks)
                        rem_p = rem_p + plan_parks(k+1);
                    end
                end
                needO = rem_t*cons.MO + rem_p*cons.PO;
                needH = rem_t*cons.MH + rem_p*cons.PH;
                needF = rem_t*cons.MF + rem_p*cons.PF;
                sp = MAX_LOAD - (state.O+state.H+state.F);
                bO = max(0, needO-state.O); bH = max(0, needH-state.H);
                bF = max(0, needF-state.F);
                if bO+bH+bF <= sp
                    cost = bO*cons.pO+bH*cons.pH+bF*cons.pF;
                    if cost <= state.M
                        state.O=state.O+bO; state.H=state.H+bH;
                        state.F=state.F+bF; state.M=state.M-cost;
                    end
                end
            elseif state.pt == 2
                fprintf('第 %d 天抵达终点 E！\n', state.day);
            end
            plan_leg = plan_leg + 1;
        end
    end
    % 输出当日状态（略，完整代码见源文件）
end
fprintf('最终: Z = %d,  M = %d\n', state.Z, round(state.M));
end
`

**CP 规划子函数** (cp_plan / cp_search_online)：

`matlab
function [best_path, best_parks, best_works, feasible] = ...
    cp_plan(cur_pt, elapsed, cons, dist, inter_idx, WY, WM, ...
            MAX_DAYS, MAX_LOAD, init_s)
    best_Z = -inf; best_M = -inf;
    best_path = [cur_pt, 2]; best_parks = []; best_works = [];
    nodes = 0;
    eff_days = MAX_DAYS - elapsed;  % 剩余可用天数
    [best_Z, best_M, best_path, best_works, best_parks, nodes] = ...
        cp_search_online([cur_pt], 0, [], [], ...
        best_Z, best_M, best_path, best_works, best_parks, ...
        dist, inter_idx, WY, WM, cons, nodes, eff_days, MAX_LOAD, init_s);
    feasible = (best_Z > -inf);
end

function [bZ,bM,bP,bWD,bPS,nodes] = cp_search_online(path, tsf, wa, ww, ...
    bZ,bM,bP,bWD,bPS, dist, inter_idx, WY, WM, cons, nodes, ...
    MAX_DAYS_EFF, MAX_LOAD, init_s)
    nodes = nodes + 1; lp = path(end);
    % 1. 上界剪枝
    if lp ~= 2
        dE = dist(lp, 2); rem = MAX_DAYS_EFF - tsf;
        if rem < dE, return; end
        ub = init_s.Z + cp_common('max_work_with_park',3,rem-dE)*28;
        if ub <= bZ && bZ > -inf, return; end
    end
    % 2. 叶节点评估：枚举工作天数 + 海上停泊组合 → 调用 cp_common('simulate')
    dE = dist(lp, 2);
    if tsf + dE <= MAX_DAYS_EFF
        fp = [path, 2]; m = length(fp) - 2; tt = 0;
        for k = 1:m+1, tt = tt + dist(fp(k), fp(k+1)); end
        rem_days = MAX_DAYS_EFF - tt; nw = length(wa);
        if nw == 0
            n_seg = m + 1;
            park_combs = cp_common('enumerate_park_combs',n_seg+1,rem_days);
            for ci = 1:size(park_combs,1)
                ps = park_combs(ci,1:n_seg);
                [ok,Z,M,~] = cp_common('simulate',fp,m,dist,[],[],...
                    tt,[],ps,cons,MAX_LOAD,init_s);
                if ok && (Z>bZ||(Z==bZ&&M>bM))
                    bZ=Z;bM=M;bP=fp;bWD=[];bPS=ps;
                end
            end
        else
            max_wk = zeros(1,nw);
            for j=1:nw
                max_wk(j)=cp_common('max_work_with_park',WM(ww(j)),rem_days);
            end
            sz = max_wk + 1; nc = prod(sz);
            for ci = 1:nc
                wd = zeros(1,nw); t2 = ci-1;
                for j=nw:-1:1
                    wd(j)=mod(t2,sz(j)); t2=floor(t2/sz(j));
                end
                total_stay = 0;
                for j=1:nw
                    if wd(j)>0
                        total_stay=total_stay+wd(j)+...
                            max(0,ceil(wd(j)/WM(ww(j)))-1);
                    end
                end
                if tt+total_stay>MAX_DAYS_EFF, continue; end
                park_rem = MAX_DAYS_EFF - tt - total_stay;
                n_seg = m + 1;
                park_combs = cp_common('enumerate_park_combs',n_seg,park_rem);
                for pci = 1:size(park_combs,1)
                    ps = park_combs(pci,:);
                    if tt+total_stay+sum(ps)>MAX_DAYS_EFF, continue; end
                    [ok,Z,M,~]=cp_common('simulate',fp,m,dist,wa,ww,...
                        tt,wd,ps,cons,MAX_LOAD,init_s);
                    if ok && (Z>bZ||(Z==bZ&&M>bM))
                        bZ=Z;bM=M;bP=fp;bWD=wd;bPS=ps;
                    end
                end
            end
        end
    end
    % 3. 分支递归：尝试每个中间点（前向检查 + 相邻去重）
    for ni = 1:5
        np = inter_idx(ni); if np == lp, continue; end
        d = dist(lp, np);
        if tsf + d > MAX_DAYS_EFF, continue; end
        dE2 = dist(np, 2);
        if tsf + d + dE2 > MAX_DAYS_EFF, continue; end
        np2 = [path, np]; nt = tsf + d;
        nwa = wa; nww = ww;
        if np >= 3 && np <= 5
            nwa(end+1) = length(np2); nww(end+1) = np - 2;
        end
        [bZ,bM,bP,bWD,bPS,nodes] = cp_search_online(np2,nt,nwa,nww,...
            bZ,bM,bP,bWD,bPS,dist,inter_idx,WY,WM,cons,nodes,...
            MAX_DAYS_EFF,MAX_LOAD,init_s);
    end
end

## 四、任务3：随机天气期望值约束规划

### 4.1 问题分析

任务3将问题扩展至 30×30 网格、90天时限、载重上限 400、初始资金 750。天气以 P(正常)=0.8、P(雷暴)=0.2 独立随机生成。船舶每日仍仅观测当日天气。

核心策略：使用**期望值消耗参数**将随机天气平滑为确定性模型，在期望值框架下运行 CP 搜索。

### 4.2 期望值消耗参数

`
E[移动] = 0.8×(2,3,2) + 0.2×(8,4,3) = (3.2, 3.2, 2.2)
E[停泊] = 0.8×(1,1,1) + 0.2×(3,3,2) = (1.4, 1.4, 1.2)
E[作业] = 0.8×(5,4,3) + 0.2×(8,6,6) = (5.6, 4.4, 3.6)
`

### 4.3 约束规划模型

与任务1、2共享完全一致的 CP 框架，仅替换消耗参数为期望值、载重上限为 400、时限为 90 天。关键变化：
- 载重上限 400 → 补给采购更灵活，不再成为瓶颈
- 时限 90 天 → 足够访问多个作业点并深度作业
- 资金 750 → 成为主导瓶颈：大量补给采购消耗资金

### 4.4 最优解

| 指标 | 值 |
|------|:---:|
| **Z** | **480** |
| **M** | **9** |
| 路径 | B → S1 → W3 → S2 → W3 → S2 → E |
| 工作安排 | W3: 3+停1+3=6天, W3: 3+停1+1=4天; 合计10天 |
| 总天数 | 87 天 / 90 |

**策略要点**：W3 作为收益最高的作业点（28/天）被访问两次，每次利用停泊重置连续作业计数器实现超限作业。资金 M 降至 9，近乎耗尽，表明已达到资金约束的极限。

## 六、模型评价与推广

### 6.1 模型优点

1. **统一框架**：CP 框架在三类天气条件下无需改动核心逻辑，仅更换消耗参数表
2. **紧致搜索**：三条剪枝规则（上界 + 前向检查 + 相邻去重）将搜索节点压缩至 ~200 以内
3. **在线实时性**：CP 搜索在 30 天时限下秒级完成规划，支持逐日在线重决策
4. **退化一致性**：同一在线模型在全雷暴和全正常下均产出与独立求解器一致的全局最优解
5. **停泊灵活价值**：发现了同一动作在正常/雷暴两种天气下分别服务于重置计数器和腾出载重空间两种策略目标
6. **可验证性**：每个任务均通过独立枚举法验证了 CP 结果的正确性

### 6.2 模型局限与改进方向

1. **期望值近似**：任务3使用期望值替代随机模拟，未考虑天气序列的方差和尾部风险 → 可推广为 MDP 使用值迭代求解
2. **递归深度**：MATLAB 默认递归深度 500，超大网格需转迭代或增加栈限制
3. **组合爆炸**：作业点增多时叶节点枚举呈指数增长 → 可引入束搜索或启发式剪枝
4. **混合天气假设**：前向假设"未来 ≡ 今日"在天气频繁突变时可能不够优 → 可引入贝叶斯更新或滚动时域随机规划

### 6.3 推广方向

- 概率版在线决策模型：引入 MDP 框架，状态值函数通过值迭代或策略迭代求解
- 多船协作（任务4）：扩展为分布式 CP 模型，加入资源交换动作空间
- 实际应用：在线决策架构天然适用于**船舶调度嵌入式控制器**
