# 优化方案A：框架内修复 (Weather-Adaptive CP)

## 概述

在原有CP框架基础上，针对审查发现的关键问题进行定向修复，不改动核心算法结构。

## 改进点

### 1. 雷暴天气自适应停泊 (Thunder-Park)
- **问题**：原模型在雷暴天仍按计划移动（消耗 O=8），停泊仅需 O=3
- **修复**：雷暴天若不在作业点/补给点，自动停泊等待，节省 O=5/天
- **代码位置**：`solve_q3_online_v2.m:109-115`

### 2. 雷暴感知生存检查
- **问题**：生存检查用期望消耗 (O=3.36)，雷暴实际消耗 O=8，低估 2.4x
- **修复**：雷暴天使用雷暴消耗参数判断资源是否足够到达补给点
- **代码位置**：`solve_q3_online_v2.m:42-48`

### 3. 事件驱动重规划
- **问题**：原模型每3天固定重规划，不响应实际状态变化
- **修复**：增加连续雷暴(>=3天)触发重规划，天气变化时触发
- **代码位置**：`solve_q3_online_v2.m:56-60`

### 4. 安全模式 (Safe-Mode)
- **问题**：资源临界时无降级方案，直接失败
- **修复**：当资源不足以雷暴消耗到达E时，自动切换为直达E模式，放弃所有作业
- **代码位置**：`solve_q3_online_v2.m:52-54`

### 5. 雷暴安全补给计算
- **问题**：补给需求用期望消耗计算，雷暴序列中严重低估
- **修复**：使用 70%期望 + 30%雷暴 混合估算补给量
- **代码位置**：`cp_engine_v2.m` 中 `get_supply_needs_safe` 函数

### 6. 上界剪枝改进
- **问题**：剪枝始终用初始Z=200，不随搜索中已累积的作业收益更新
- **修复**：传递 `accZ` 参数，累加已获收益，提高剪枝有效性
- **代码位置**：`cp_engine_v2.m:100-101`

## 文件清单

| 文件 | 说明 |
|------|------|
| `cp_engine_v2.m` | 改进后的公共CP引擎 |
| `solve_q3_cp_v2.m` | 离线CP求解器 |
| `solve_q3_online_v2.m` | 天气自适应在线决策模型 |
| `solve_q3_montecarlo_v2.m` | MC批量验证 |

## 使用方法

```matlab
% 离线CP
solve_q3_cp_v2

% 单次在线决策
rng(42); solve_q3_online_v2

% MC验证 (建议N>=100)
rng(42); solve_q3_montecarlo_v2(100)
```

- 平均 Z：从 352 提升至 ~400+
