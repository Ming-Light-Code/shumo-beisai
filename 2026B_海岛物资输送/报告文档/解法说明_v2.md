# 问题三 改进解法说明：CCASR 方法

## 一、原模型缺陷回顾

原模型 (solve_q3_v2.m) 采用四阶段确定性近似方法，存在以下核心问题：

### 1.1 方法论层面

| 问题 | 说明 |
|------|------|
| 确定性退化 | 将随机动态规划退化为 certainty-equivalent approximation：用期望消耗替代表格随机参数做 MILP 规划 |
| 先验信息未充分利用 | 仅用一阶矩（期望值），丢弃了方差信息。P(N)=0.8, P(S)=0.2 的 Bernoulli 分布被压缩成单一期望值 |
| SDP 公式未实现 | 解法说明写了 V_t(s,w) 的 Bellman 方程，但代码未做任何后向递推或状态空间价值函数近似 |

### 1.2 算法层面

| 问题 | 说明 |
|------|------|
| 骨架约束过强 | 仅允许 0-4 个不重复中间 POI，排除了 B->W3->S2->W3->E 这类回访策略 |
| Phase 4 不是真正重优化 | 名为滚动时域，实为按固定计划的顺序执行 + 一条燃油阈值跳过 |
| Phase 3/4 不一致 | SAA 评估用 sim_path_q3（固定计划），Phase 4 用 phase4_daily（有跳过逻辑），选优与执行评估不同策略 |

### 1.3 结果可靠性

| 问题 | 说明 |
|------|------|
| Z=368 仅排除更优路径 | B->W1->S1->W3->E 理论 Z=448，B->S1->W2->S2->W3->E 理论 Z=518，模型草率断言成功率低 |
| 缺统计推断 | 500 场景无置信区间，无敏感性分析 |
| 安全缓冲无推导 | VM=0.16*[6,1,1]^2 和 Zf=2 的选择缺乏统计证明 |

## 二、新方法：Chance-Constrained Adaptive Stochastic Rollout (CCASR)

### 2.1 核心思想

不从期望值规划，而从分布规划。利用已知的天气概率先验，在三个层面引入随机性：

1. MILP 规划层：用方差导出的安全裕度（chance constraint）替代固定安全缓冲
2. 策略评估层：用 2000 场景 Monte Carlo 模拟 + 全适应性规则选出最优策略
3. 在线执行层：每天观测天气后，根据实际消耗和剩余资源做适应性决策

### 2.2 数学框架

问题形式化：

状态空间 S: (x,y) in {1,...,30}^2 x O x H x F x M x Z x cw x day

动作空间 A(s,w):
- Move: 消耗 CM(w)，移动一格，cw<-0
- Work: 消耗 CW(w)，Z<-Z+WY(k)，cw<-cw+1（仅当处于作业点且 cw<WM）
- Moor: 消耗 CS(w)，cw<-0
- Supply: 消耗 CS(w)，采购资源，cw<-0（仅当处于补给点）

随机性：w_t ~ Bernoulli(0.2)，独立同分布

目标（字典序）： max Z(90)；同 Z 时 max M(90)

### 2.3 方差推导

对动作类型 a in {Move, Work, Moor/Supply}，其燃油日消耗是 Bernoulli 随机变量：

O_cost(a) ~ { mu_n(a) w.p. 0.8, mu_s(a) w.p. 0.2 }

E[O_cost(a)] = 0.8*mu_n + 0.2*mu_s = mu_e(a)
Var[O_cost(a)] = 0.8*0.2*(mu_s - mu_n)^2 = 0.16*(mu_s - mu_n)^2

具体数值：
- Var_move_O = 0.16*(8-2)^2 = 5.76
- Var_move_H = 0.16*(4-3)^2 = 0.16
- Var_work_O = 0.16*(8-5)^2 = 1.44
- Var_work_H = 0.16*(6-4)^2 = 0.64

任意计划由 Dm 天移动、Dw 天作业、Ds 天停泊组成，总消耗方差：
Var[O_total] = Dm*5.76 + Dw*1.44 + Ds*0.64

Chance Constraint（95% 单侧置信）：
P(O_final >= 0) >= 0.95
等价于 Initial_O + Buy_O - E[O_total] - z_0.95*sqrt(Var[O_total]) >= 0
其中 z_0.95 = Phi^{-1}(0.95) = 1.645

### 2.4 算法架构

Phase A: 策略生成
  - 枚举候选 POI 序列（含回访：W3->S2->W3）
  - 对每个序列，用两阶段 MILP 确定最优工作天数和采购量
  - 按 Z 排序，取前 20 个候选策略

Phase B: 策略评估（MC Rollout）
  - 对每个候选策略，模拟 2000 个天气场景
  - 模拟中使用适应性规则：
    - 雷暴天移动资源紧张 -> 改为停泊
    - 作业前检查资源 -> 不够则跳过改为停泊
    - 补给点动态计算采购量（基于剩余期望+安全缓冲）
  - 按 E[Z] 选出最优策略

Phase C: 在线执行
  - 按最优策略的骨架顺序执行
  - 每天观测实际天气
  - 雷暴天：自适应决策（移动/停泊/作业跳过）
  - 补给点：动态计算最优采购量
  - 记录完整执行日志

### 2.5 关键改进点对比

| 维度 | 原方法 | CCASR |
|------|--------|-------|
| POI 访问 | 不重复 | 允许回访（W3->S2->W3） |
| 候选策略数 | ~781 条骨架 | 20 条候选 + 适应性分支 |
| 规划消耗 | 期望值 | 期望值 + 方差安全裕度 |
| 策略评估 | 500 SAA (固定计划) | 2000 MC (全适应性) |
| 在线决策 | 燃油阈值跳过 | 阈值 + 天气条件判断 + 动态补给 |
| 补给策略 | 固定公式 | 基于剩余路径期望+方差的动态计算 |
| 统计报告 | 无 CI | 期望值 + 成功率 |

## 三、运行方式

```matlab
>> solve_q3_new
```

需要 Optimization Toolbox（intlinprog）。自动运行全部三个阶段（A/B/C）。

## 四、代码结构

| 函数 | 功能 |
|------|------|
| solve_q3_new | 主函数，运行全部三个阶段 |
| gen_policies | 生成候选 POI 序列（含回访） |
| milp_seq | 两阶段 MILP：Stage1 max Z, Stage2 max M |
| total_days | 计算策略所需总天数 |
| mc_eval | Monte Carlo 策略评估（2000 场景） |
| sim_one | 单条天气场景下的适应性模拟 |
| adap_sup | 自适应补给计算（期望+方差安全缓冲） |
| online_exec | 在线执行（天气观测+适应性决策） |
