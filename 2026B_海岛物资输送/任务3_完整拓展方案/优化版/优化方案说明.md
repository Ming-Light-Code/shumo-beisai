## 一、差异化安全裕度 (P0)

### 1.1 设计原理

雷暴对不同资源的消耗放大倍数差异显著：

| 动作 | 正常O→雷暴O | 正常H→雷暴H | 正常F→雷暴F |
|------|:---:|:---:|:---:|
| 移动 | 2→8 (4×) | 3→4 (1.3×) | 2→3 (1.5×) |
| 停泊 | 1→3 (3×) | 1→3 (3×) | 1→2 (2×) |
| 作业 | 5→8 (1.6×) | 4→6 (1.5×) | 3→6 (2×) |

O（燃油）是所有动作中雷暴放大最剧烈的资源。均匀10%裕度对O远不够，对H/F略过度。

### 1.2 实现

```matlab
SAFETY_O = 1.25;  % 燃油: 移动4倍放大
SAFETY_H = 1.05;  % 淡水: 最大放大1.5倍
SAFETY_F = 1.05;  % 食物: 最大放大2倍

cons_exp.MO = 3.2 * SAFETY_O;   % = 4.0 (vs 原版 3.52)
cons_exp.MH = 3.2 * SAFETY_H;   % = 3.36 (vs 原版 3.52)
cons_exp.MF = 2.2 * SAFETY_F;   % = 2.31 (vs 原版 2.42)
```

关键变化：移动O消耗从3.52→4.0（增加13.6%），移动H消耗从3.52→3.36（减少4.5%）。

## 二、补给预防性超购 (P1)

### 2.1 设计原理

原版供给算法：
```
bO = max(0, needO - currentO);  // 刚好够到下一站
```

优化版：
```
bO = max(0, needO - currentO);
spare_after = MAX_LOAD - (O+H+F + bO+bH+bF);
buffer_O = 0.10 * spare_after;  // 10%剩余空间作为缓冲
bO = bO + buffer_O;
```

在载重上限400下，剩余空间通常有几十单位，10%缓冲是几单位资源。代价极小（约增加2-3%采购成本），但能吸收数个雷暴日的额外消耗。

### 2.2 边界处理

- 缓冲不超过剩余空间的10%
- 缓冲总量受资金 M 约束
- 最后一段补给（到E前）不使用缓冲（抵达E后不需要余量）

## 三、生存优先模式 (P2)

### 3.1 触发条件

在每次CP重规划前检查：

```matlab
dist_to_nearest_supply = min(dist(pt, S1), dist(pt, S2));
O_needed_expected = dist_to_nearest_supply * cons_exp.MO;
survival_mode = (state.O < 1.5 * O_needed_expected);
```

当船舶燃油不足最近补给点期望需求的1.5倍时，激活生存模式。

### 3.2 行为变化

生存模式下，CP搜索的目标从"最大化Z"变为"确保抵达E"，具体：
- 路径骨架仅包含补给点和E，不含作业点
- 工作天数强制为0
- 优先选择到最近补给点的最短路径

### 3.3 退出条件

抵达补给点并完成采购后，重新评估：若O恢复到安全水平，退出生存模式恢复正常CP规划。

## 四、代码重构 (P4)

### 4.1 公共库 cp_engine_opt.m

抽取三个求解器共用的核心函数：

| 函数 | 功能 |
|------|------|
| `cp_search_engine()` | CP递归搜索（路径骨架 + 三剪枝） |
| `simulate_path()` | 期望/实际消耗路径模拟 + 补给决策 |
| `max_work_with_park()` | 工作天数上界计算 |
| `plan_from_state()` | 从当前状态出发的CP规划入口 |
| `generate_weather_seq()` | 随机天气序列生成 |

### 4.2 文件依赖关系

```
cp_engine_opt.m (公共库)
    ↑              ↑              ↑
solve_q3_cp_opt.m  solve_q3_online_opt.m  solve_q3_montecarlo_opt.m
```
