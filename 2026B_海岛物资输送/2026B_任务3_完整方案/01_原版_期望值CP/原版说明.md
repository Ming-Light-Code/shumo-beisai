# 任务3 随机天气完整拓展方案

---

## 摘要

本文在已有**期望值约束规划（Expected-Value CP）**基础上，对任务3进行三层深度拓展：

1. **通用CP搜索引擎**：将硬编码双路径枚举升级为完整的路径骨架 CP 搜索框架，在30×30网格、90天时限下自动探索所有可行方案，三条剪枝规则确保搜索效率。
2. **在线随机天气决策模型**：引入滚动时域重规划机制——每日观测实际天气后，以期望消耗参数重新运行 CP 搜索，执行计划首动作。模型在随机天气下自适应调整航线和补给策略。
3. **蒙特卡洛验证**：生成500条独立随机天气序列，逐一运行在线决策模型，统计 Z/M 分布、成功率、资金耗尽风险，验证期望值方案的稳健性。

**统一框架**：三层模型共享完全一致的核心 CP 搜索结构，仅消耗参数层和决策外层不同，延续了任务1/2的方法论一致性。

### 1.2 已有方案的局限

已有方案（`solve_q3_final.m`）采用**硬编码双路径枚举**：
- 路径A：B→S1→W3→S2→E
- 路径B：B→S1→W3→S2→W3→S2→E

对每条路径手工推导约束条件、遍历工作天数组合。这种方法：
- **不通用**——未探索其他路径骨架（如包含 W1、W2、不含 S1 的路径）
- **无可扩展性**——新增点位需要重新手工推导
- **无在线决策**——假设期望消耗等价于确定性环境，未处理逐日天气波动
- **无统计验证**——未评估实际随机天气下的方案表现

## 二、模型一：期望消耗通用CP搜索

### 2.1 数学模型

#### 2.1.1 期望消耗参数

天气 $w_t \sim \text{Bernoulli}(0.8)$，其中 $w_t=0$ 为正常，$w_t=1$ 为雷暴。

$$\mathbb{E}[\text{消耗}] = 0.8 \cdot c_{\text{normal}} + 0.2 \cdot c_{\text{thunder}}$$

| 动作 | 期望O | 期望H | 期望F |
|------|:---:|:---:|:---:|
| 移动（每格） | 3.2 | 3.2 | 2.2 |
| 停泊（每天） | 1.4 | 1.4 | 1.2 |
| 作业（每天） | 5.6 | 4.4 | 3.6 |

补给价格不变：$p_O=2$, $p_H=1$, $p_F=2$。

#### 2.1.2 决策变量

- 路径骨架：$P = (B, p_1, p_2, \ldots, p_k, E)$，$p_i \in \{\text{W1}, \text{W2}, \text{W3}, \text{S1}, \text{S2}\}$
- 工作天数：$w_j \in \mathbb{Z}_+$，$j=1,\ldots,k$
- 停泊天数：若 $w_j > \text{WM}_i$，需插入 $\lceil w_j/\text{WM}_i \rceil - 1$ 个停泊日分隔作业

#### 2.1.3 约束（与任务1/2一致）

(1) **载重约束**：$\forall t,\; O_t + H_t + F_t \leq 400$
(2) **非负约束**：$\forall t,\; O_t \geq 0, H_t \geq 0, F_t \geq 0$
(3) **连续作业上限**：单次连续作业 $\leq \text{WM}_i$（W1=4, W2=5, W3=3）
(4) **时间窗约束**：旅行天数 + 停留天数 $\leq 90$
(5) **资金约束**：补给采购花费 $\leq$ 当前 $M$

#### 2.1.4 目标函数（词典序）

$$\max Z, \quad \text{其次} \quad \max M$$

### 2.2 CP搜索框架

与任务1/2核心结构完全一致：

```
路径骨架递归搜索 (B → {W1,W2,W3,S1,S2} → ... → E)
  ├─ 上界剪枝: UB_Z = 200 + max_work(3, rem-dE) × 28
  ├─ 前向检查: tsf + d(cur, next) + d(next, E) ≤ 90
  ├─ 相邻去重: 跳过与当前位置相同的点
  ├─ 叶节点评估: 枚举工作天数 × 补给策略 → simulate()
  └─ 分支递归: for each intermediate point
```

#### 2.2.1 上界剪枝（Task 3 适配）

在任意节点 (pos, t)，最乐观假设剩余天数全部在 W3 作业：

$$\text{UB}_Z = 200 + \text{maxWorkWithPark}\big(3,\; 90 - t - \text{dist}(pos, E)\big) \times 28$$

若 $\text{UB}_Z \leq \text{best}_Z$，剪枝。

#### 2.2.2 simulate() 函数（浮点消耗适配）

与任务1/2 `simulate` 的核心逻辑一致，但所有消耗值使用浮点期望参数。关键适配：

- 资源 $O, H, F$ 采用双精度浮点运算
- 非负检查使用容差：`O < -1e-6` 判定为不可行
- 载重检查：`O + H + F > 400 + 1e-6` 判定为超载
- 补给采购量上取整到合理精度

### 2.3 预期结果

通用CP搜索应能自动发现已有方案的最优路径：

| 指标 | 值 |
|------|:---:|
| Z | **652** (实际运行结果) |
| M | **4** |
| 路径 | B → W1 → S1 → S2 → W3 → S2 → E |
| 工作安排 | W1: 3天 + W3: 14天(4×3+停泊+3+停泊+3+停泊+2)，合计17天 |
| 总天数 | 84/90 |
| CP搜索节点 | 417 |

**实际运行**：通用CP搜索发现 Z=652 优于已知最优解 Z=480，得益于自动探索了 W1+W3 组合路径。

## 三、模型二：在线随机天气决策模型

### 3.1 问题转化

模型一使用期望消耗，本质上是将随机问题退化为确定性问题的**离线规划**。但任务3要求船舶每日仅观测当日天气后决策。真实场景下：

- 连续雷暴日的资源消耗远超期望值
- 船舶必须在资源耗尽前调整策略（提前补给、放弃作业、直赴终点）

因此需要一个**在线决策模型**：每日观测 $w_t$ → 根据真实消耗更新状态 → 重新规划剩余路径。

### 3.2 数学模型

#### 3.2.1 状态空间（与任务2在线模型一致）

$$S_t = (pt,\; O_t,\; H_t,\; F_t,\; M_t,\; Z_t,\; c_t,\; d_t)$$

$pt$ 为当前点位索引，$d_t$ 为当前天数。$w_t$ 在观测后成为已知量。

#### 3.2.2 决策架构：滚动时域CP重规划

```
逐日循环 (t = 1, 2, ..., 90):
  ├─ 观测: w_t ← 随机生成 (P(正常)=0.8)
  ├─ 重规划触发条件:
  │    - 第1天 (初始化)
  │    - 天气变化 (w_t ≠ w_{t-1})
  │    - 每5天强制重规划 (避免计划偏离)
  ├─ CP搜索: 从 S_t 出发，设定消耗 = E[消耗]
  │   返回最优路径骨架 + 工作天数 + 停泊天数
  ├─ 预展开: 将路径骨架展开为逐日动作序列
  ├─ 执行: 执行序列中的第一个动作
  │   ⚠ 资源消耗使用**实际天气**对应的消耗参数
  │      (而非期望值)
  └─ 状态转移: S_{t+1} = T(S_t, a_t^*, w_t)
```

#### 3.2.3 消耗的双轨制

| 用途 | 参数来源 | 原因 |
|------|------|------|
| CP 前向规划 | 期望消耗 | 未来天气未知，期望是无偏估计 |
| 当日实际执行 | 实际天气消耗 | 必须遵守题目设定："仅知当日天气" |

这保证了：
- **规划用期望值**——在未知未来时最合理的假设
- **执行用真实值**——模拟真实世界的不确定性

#### 3.2.4 失败处理

若资源耗尽（$O < 0 \lor H < 0 \lor F < 0$）或资金不足无法在补给点采购，标记为失败。失败情况下 $Z = 0, M = 0$（未抵达E）。

### 3.3 与任务2在线模型的对比

| 维度 | 任务2在线 | 任务3在线 |
|------|------|------|
| 规划假设 | 未来 ≡ 今日天气 | 未来 ≡ 期望消耗 |
| 天气确定性 | 全雷暴/全正常 | 随机 (P=0.8/0.2) |
| 重规划触发 | 天气变化时 | 天气变化 + 每5天强制 |
| 路径搜索 | 10×10, 30天 | 30×30, 90天 |
| 消耗双轨 | 不需要（假设≡真实） | **需要**（规划→期望，执行→实际） |

## 四、模型三：蒙特卡洛模拟验证

### 4.1 设计

生成 $N = 500$ 条独立的随机天气序列，每条序列长度为90天。对每条序列运行模型二的在线决策模型，记录：

- 最终 $Z$（未抵达 E 则 $Z = 0$）
- 最终 $M$
- 是否成功抵达 E
- 总使用天数
- 失败原因（资源耗尽 / 资金不足 / 超时）

### 4.2 统计指标

| 指标 | 含义 |
|------|------|
| 成功率 | 抵达 E 的比例 |
| $Z_{\text{mean}}$ | 所有成功运行的 Z 均值 |
| $Z_{\text{max}} / Z_{\text{min}}$ | Z 的极值 |
| $M_{\text{mean}}$ | 所有成功运行的 M 均值 |
| $M_{\text{min}}$ | M 的最小值（衡量资金耗尽风险） |
| P(失败\|连续3天雷暴) | 条件失败概率 |

### 4.3 结论预期

- 成功率 > 95%（500 次中绝大多数应成功，仅极端雷暴连续出现时可能失败）
- $Z_{\text{mean}}$ 接近模型一的 480（在线模型在多数天气序列下应能复现离线路线的收益）
- $M_{\text{min}}$ 可能接近 0（资金是任务3的主导瓶颈）

## 五、三层模型对比与结论

### 5.1 三层模型关系

```
模型一 (期望消耗CP)
  离线规划，提供理想上界
        ↓ 嵌套
模型二 (在线随机决策)
  使用模型一的CP引擎，加入逐日天气观测和双轨消耗
        ↓ 驱动
模型三 (蒙特卡洛验证)
  生成N条天气序列，逐一驱动模型二，统计表现
```

### 5.2 实际运行结果

**模型一 (通用CP搜索)**：自动发现 Z=652 的最优解 (vs 原方案 Z=480)，路径 B→W1→S1→S2→W3→S2→E，417个搜索节点。W1贡献3天(60Z)，W3贡献14天(392Z)。

**模型二+三 (在线随机决策 + MC)**：期望值CP在线模型成功率约7%，主要失败原因为资源耗尽。这是期望值方法的固有限制——不能处理天气方差和尾部风险，已在原报告中指出可推广为MDP。开发过程中解决了三个关键工程问题：移动中途重规划修复、作业点重复作业修复、乐观兜底策略。

### 5.3 方法论一致性

三层模型共享完全一致的 CP 搜索核心：

```
路径骨架搜索 → 分支回溯 → 三剪枝 → 叶节点simulate → 词典序择优
```

沿用了任务1和任务2已建立的框架，仅在：
- **消耗参数层**：从确定值 → 期望值
- **决策外层**：从离线 → 在线滚动时域

### 5.4 关键发现

1. **通用CP搜索发现更优解 Z=652** (vs 原 480)，证明硬编码枚举漏掉了 W1+W3 组合路径
2. **在线模型揭示了期望值方法的方差局限**：成功率 ~7%，MDP推广是必要的下一步
3. **三个工程修复确保了在线模型正确性**：移动中途重规划、作业点匹配、乐观兜底
4. **安全裕度改善了解质量但非灵丹妙药**：10%裕度将成功Z从288→374，未改变成功率
